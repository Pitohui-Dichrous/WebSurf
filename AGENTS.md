# WebSurf release rules

- `version.properties` is the only editable version source. Gradle, the app label and packaging read it. Never hardcode a release name in Java or increment versions during ordinary builds.
- The UI format is `//version. <versionName>`. Main uses `0.7.0-main`; the `酸性设计` branch uses `0.6.1-acid.2`. Preview ordinals count releases across base versions, not Git commits or builds. A later acid release after `acid.2` uses `acid.3` even if its base changes to `0.7.0`.
- Run `python scripts/version.py prepare --patch` for small fixes, `--minor` for the next minor release, or `--version X.Y.Z` when the user requests a specific base. The helper refreshes tags from origin (aborting if that fails), selects the channel, increments Android versionCode and the preview ordinal, and updates README/USAGE links. On other named branches, provide `--channel slug` the first time. Re-running prepare on an unreleased version is guarded; do not bypass it by editing metadata.
- Before publishing, run `python scripts/version.py check --unreleased`. Main/master map to `main`; `酸性设计` maps to `acid`. If metadata belongs to another branch, prepare that branch's next version first. Detached tag and source-archive builds intentionally reproduce stored metadata.
- Build and verify the intended release APK. Packaging must check its actual build version/name/code and verification summary against the metadata; never rename an older APK to satisfy a new filename. Include `version.properties` and this file in source archives.
- Record checks actually performed for this release in `docs/release-verification.json`; distinguish inherited baseline tests from tests rerun now. Keep tools, signing secrets, private diagnostics and APK inputs out of Git/source archives.
- Tag releases as `v<versionName>`. Publish `main` as stable and other channels as prereleases; a hyphen in the version alone does not determine the channel. Keep stable/latest unchanged when publishing acid previews. Verify public downloads and hashes after upload.
