# WebSurf 使用与构建

版本：**0.6.1-acid.4**，`酸性设计` 分支的公开预览版。稳定版仍为 0.5.0。

本版直接使用用户提供的 WS.png 原图作为图标，以黑白、荧光绿、硬边色块和粗窄展示字体重构浏览器工具栏、资源、下载、菜单和设置。中文操作保留系统字体，下载数据使用等宽数字；浅色和深色主题采用对应的色彩关系。网页内容保持站点原有设计，网页接管按钮与应用控件采用相同视觉语言。详情见 [设计说明](ACID_DESIGN.md)。

## 使用

安装 `WebSurf-0.6.1-acid.4.apk`。首次打开为 `https://www.baidu.com`。右下角菜单 → 设置 → 主页，可保存其他网址；点击底部主页图标打开。

点击网页视频播放后，WebSurf 在原视频位置接管，随页面滚动和裁剪。默认不会弹出小窗；后台自动播放的视频仅被记录，不会凭加载顺序抢占。每个视频独立管理，切换视频可点击原网页对应视频，或在播放器的更多菜单中选择。

播放器提供播放/暂停、进度、倍速、静音、下载、全屏和手动浮窗。横向视频进入全屏自动横屏，退出恢复原方向。全屏支持锁定、左右滑动调进度、左侧上下滑动调亮度、右侧上下滑动调音量；长按画面临时 2 倍速，松手恢复。浮窗顶部可拖动。三种显示模式共用同一个播放实例；更多菜单提供前后 15 秒跳转。原位播放时可以直接从画面纵向滑动页面，松手后保留惯性；视频经过页面顶部时随滚动距离平滑展开并吸顶，避开地址栏。反向滑动会沿原路径恢复原位。已吸顶后暂停保持位置，未播放的视频不会主动吸顶。菜单另提供 Android 系统小窗。

点击播放器关闭或底部“网页播放”会把进度交还该网页视频，保留网页、滚动和输入。该视频暂时不再自动接管；其他视频仍可正常选择。在网页切换清晰度后，点击底部“接管播放”或视频下方右侧的同名按钮即可恢复，无需刷新整页。网页接管按钮与底部按钮均跟随应用的浅色/深色设置；网页按钮占用视频下方独立一行，不覆盖画面或网页视频控制。设置中的“自动接管视频”是全局开关；关闭自动接管后仍可手动接管。

需要换画质时，先切回“网页播放”，使用网站自己的清晰度入口，再点“接管播放”，无需刷新整页。接管播放器不提供画质菜单或首选画质设置，也不根据保存的偏好改写网页视频来源；资源列表仍保留实际清晰度与像素尺寸。首次从网页切到原生播放器时，页面、进度等状态可以保留，但 Android WebView 已缓冲的数据和解码器不能直接转交给当前的 Media3 实现，因此仍可能重新请求、缓冲视频；本版本不承诺零缓冲接管。

正在接管时，网页的播放、暂停、进度和结束事件与内置播放器同步。片前广告结束后，网页脚本可按原有逻辑切换到正片。此实现针对可直接访问的 HTTP(S) 视频；无法可靠绑定到某个视频的媒体源不会猜测替换。

原位接管发生原生播放错误时，应用自动移除覆盖画面并恢复原网页 video 的进度和播放意图，不刷新网页，也不向网页伪造 MediaError。同一失败源不会反复自动接管；仍可手动重试，且该 video 切换到新来源后可继续接管主视频。用户主动选择“网页播放”则会保持网页模式，直到再次手动接管。从资源列表独立打开的视频没有对应网页元素，失败时仍保留错误与重试入口。

网页资源面板持续收集当前标签页的请求地址、DOM 媒体与可见响应类型，按视频、音频、图片和其他分类。分类按钮与资源列表之间保留独立间距。列表提供网页封面、可提取的视频帧或当前播放画面的缩略图，并明确标出预览来源。清晰度显示为如“720p · 1280 × 720”；HLS 主列表的可选清晰度与最高档单独标明，不能识别时显示“清晰度待识别”。预览只在列表可见时异步读取，HLS 预览不下载视频分片，未提供封面的 HLS 可在接管播放后使用实际画面。每页最多保留 400 个地址，但面板不再显示该说明页脚。点击条目可以预览、下载、复制链接或查看完整地址。资源嗅探是被动观察，不要求重新加载网页；部分资源仍需先播放或滚动才会出现。

资源列表使用用户提供的音频、文档和暂无预览图标。读取预览时播放原始 GIF，完成、隐藏或离开屏幕后停止；系统关闭动画时显示静态画面。预览失败可点击图标重试。

直接提取视频缩略图时优先解码第 3 秒画面，短视频使用首帧；读取失败保留首帧回退。网页封面仍优先使用原站提供的封面，HLS 不额外下载分片来取帧。接管播放器会等播放越过开头 3 秒后再缓存画面，避免片头黑屏覆盖预览；预览不会跳转视频的播放位置。

顶部下载图标打开任务列表。普通文件按原字节保存；m3u8 先下载分片，随后合并为真正的 MP4。主播放清单默认选最高带宽版本；单一画质清单保留该画质。合并不提高画质，也不强制重新编码。Android 10 及以上保存到系统 `Download/WebSurf`。Android 8–9 使用应用专属下载目录，可从任务列表打开文件。音视频文件可在应用内播放。

`remote_control.php` 等通用脚本地址不再直接作为视频名称，优先使用网页视频标题。服务器响应提供真实文件名时，下载保存采用该文件名；缺少可用名称时使用通用视频名称。

设置 → “下载并发”可选择 1、2、4、8 或 16 路，默认为 8 路，实际连接数由文件和服务器条件决定。HLS 同时读取有限数量的分片，并按播放清单顺序合并。普通 HTTP 文件须至少 2 MiB、服务器声明支持 Range，且提供可校验的稳定 ETag 或 Last-Modified，才尝试分块下载；每块至少 512 KiB，小文件会减少连接数或使用单路。服务器忽略区间、内容标识变化或区间读取异常时，会停止分块、使相关共享缓存失效，并从头单路下载，避免混合不同版本的文件。并发不保证按路数成倍提速，速度还取决于网络、磁盘和服务器限制。

中途修改并发设置只影响之后开始执行的任务；正在下载的任务保留启动时的并发数量，持续下载并正常刷新进度，不会因修改设置而重启。

任务列表显示实际下载字节数、已知总量、每秒传输量及 HLS 已完成/总分片数，并区分下载、合并 MP4 和保存文件。总量未知时不伪造总大小。进度更新保留现有任务行，不因每次收到数据重建整个列表。同一地址的活动下载会进入已有任务。开始、完成和失败会提供系统通知；应用在前台时也显示可打开任务或文件的反馈。拒绝通知权限不妨碍下载，仍可在应用内查看状态和完整错误。

进行中的视频任务可点“边下边播”。下载已写入共享缓存的数据可供内置播放器读取，缺失部分按正常网络流程请求；下载持续推进，不随播放进度节流。缓存仅在同一来源、相同请求凭据范围内共享。跨 CDN 的资源仍可正常播放和下载，但不共享这部分缓存；播放器已经打开的网络读取不会立即改走后来产生的缓存，网页原播放器也不使用该缓存。因此不能保证所有视频都减少重复请求，缓存也不等于离线文件。

下载支持取消、失败原因和重试，尚未提供暂停或断点续传。取消后重试、失败重试均从头请求。系统终止应用后，未完成任务会显示中断，用户可重试。已结束任务可“移除记录”，只移除列表记录，保留已下载文件；文件可在系统文件管理器中管理。下载期间应保留足够空间供缓存和最终文件使用。

## 范围

浏览器使用 Android 系统提供的 Chromium WebView，实际内核版本可在设置查看；没有把完整 Chrome APK 嵌入应用。系统 WebView 可独立更新。普通页面滚动使用 WebView 原生回调同步播放器；iframe 内部滚动、fixed/sticky 和复杂 CSS 容器依靠网页逐帧更新，不能保证与 QQ 的私有内核完全相同。

当前版本不处理 DRM/SAMPLE-AES、仍在进行的直播、HLS 不连续时间轴或中途更换初始化片段。部分 blob/MSE、私有播放器、仅 POST 返回的资源及站点专有授权流程可能无法导出；嗅探到地址不等于该地址一定可以下载。DASH MPD 可作为网页资源被发现，但不提供 DASH 合并导出。

## 构建

需要 Java 17、Android SDK 35 和网络上的 Maven/Gradle 依赖。设置 `JAVA_HOME` 与 `ANDROID_HOME` 后，在项目目录执行：

```powershell
.\scripts\build.ps1 :app:assembleDebug
```

脚本优先使用已有环境变量，其次寻找本项目 `.tools` 和本机 `E:\MediaMaster\.tools` 中的现有工具链。Gradle Wrapper 固定为 8.11.1，并校验下载摘要。首次构建需要联网。

签名版构建：

```powershell
.\scripts\build.ps1 :app:assembleRelease
```

本机发布签名保存在 `.tools/signing/`，请保留以便覆盖升级。源码压缩包不包含签名私钥、工具缓存、原始 QQ 浏览器 APK 或反编译代码；没有签名配置时，release 构建产物为未签名 APK，debug 构建使用独立包名 io.websurf.app.debug，可与正式版共存。

## 测试

```powershell
.\scripts\build.ps1 :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
node --test scripts/test_sniffer.mjs
python scripts/fixture_server.py
```

浏览器集成测试要求设备能够访问本机测试服务器；模拟器可用 `adb -s emulator-5560 reverse tcp:8765 tcp:8765`。明确指定测试设备，再安装两份 debug APK 并运行：

```powershell
adb -s emulator-5560 shell am instrument -w -e class io.websurf.app.PlayerRecoveryTest,io.websurf.app.ResourcePanelLayoutTest,io.websurf.app.BrowserFlowTest,io.websurf.app.VideoControlsTest,io.websurf.app.ScrollPlaybackTest,io.websurf.app.ThemeResourceUiTest,io.websurf.app.ResourcePreviewTest,io.websurf.app.DownloadExperienceTest,io.websurf.app.MediaTransferCacheTest,io.websurf.app.download.DownloadEngineInstrumentedTest,io.websurf.app.UiCaptureTest io.websurf.app.debug.test/androidx.test.runner.AndroidJUnitRunner
```

`scripts/generate_fixtures.py` 可重新生成浏览器测试媒体，需要本地 FFmpeg。测试夹具仅放在 androidTest 中，不会进入正式 APK。
